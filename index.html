Une approche en trois étapes

Comprendre avant
d'agir.

Un premier contrôle utile aux développeurs, sans promettre l'impossible : chaque résultat mérite d'être vérifié.

01 / DÉTECTER

Repérer les signaux

Le projet n'est pas exécuté. Des règles recherchent certains secrets possibles. Le mode approfondi examine aussi les dépendances et montre les éléments ignorés.

02 / VÉRIFIER

Consulter OSV, si choisi

Pour certaines versions npm et Python exactes, une recherche facultative retrouve des avis publics. La gravité et la correction doivent être vérifiées dans chaque avis.

03 / AGIR

Passer à l'action

Chaque rapport explique le constat et sépare les informations publiques des alertes. Pour un vrai secret exposé, révoquez-le d'abord, puis nettoyez les fichiers et l'historique.

Pensé pour la transparence

Vos données,
vos décisions.

Le rapport ne recopie pas volontairement les lignes sources ni les valeurs détectées. Les chemins et noms de paquets peuvent toutefois être sensibles : vérifiez-les avant de partager un rapport.

À savoir avant de lancer l'analyse

OSV est facultatif. Si vous l'activez, les noms, écosystèmes et versions exactes des paquets inventoriés sont transmis à OSV ; pas les fichiers ni les extraits de code.

La couverture est limitée. L'historique Git, les binaires et plusieurs formats de dépendances ne sont pas analysés. Un rapport vide ne garantit pas la sécurité du projet.
